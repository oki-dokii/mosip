# Local JSON-LD compatibility findings

Observed during the 25–26 October 2026 local integration. These are version-specific observations, not confirmed upstream issues. No issue was filed. The [connected runbook](INJI_WEB_LOCAL.md) documents the working fixture and its limits.

| Observation | Reproduction and deciding evidence | Resolution in this fixture |
| --- | --- | --- |
| Certify 1.0.0-alpha.1 rejects Mimoto 0.22.0's `Ed25519` JWS proof | With `Ed25519` advertised, the wallet sent that algorithm with matching client, audience and nonce. Certify logged `Signed JWT rejected: Another algorithm expected, or no matching key(s) found`. The [alpha validator](https://github.com/inji/inji-certify/blob/v1.0.0-alpha.1/certify-service/src/main/java/io/mosip/certify/proof/JwtProofValidator.java) has a special verification branch for `EdDSA` only; the [0.14 validator](https://github.com/inji/inji-certify/blob/v0.14.0/certify-service/src/main/java/io/mosip/certify/proof/JwtProofValidator.java) includes both. | Pin official 0.14.0 for this JSON-LD flow. Keep the successful alpha SD-JWT profile separate. No product code patch. |
| An RSA issuance fallback changes the bound wallet key | RSA issuance succeeded, but Mimoto's [presentation service](https://github.com/inji/mimoto/blob/v0.22.0/src/main/java/io/mosip/mimoto/service/impl/WalletPresentationServiceImpl.java) selects its Ed25519 key. Verify returned `ERR_HOLDER_BINDING_CHECK_FAILED` for the RSA-bound credential. | Issue with the wallet's Ed25519 key. Normalize the template's subject URI to the same base64url key reference with `#0`; the bridge records a boolean comparison of the actual public keys. |
| Certify's public DID document uses the DID as `assertionMethod` | The public document contained `assertionMethod: [did]`, while its actual signing verification method had a fragment. The [tagged implementation](https://github.com/inji/inji-certify/blob/v0.14.0/certify-service/src/main/java/io/mosip/certify/utils/DIDDocumentUtil.java) constructs that relationship. | The explicit local DID adapter references the unchanged Ed25519 verification method. The resulting pass is not a pass of the unadapted DID relationship. |
| Encoded-port DID resolution and localhost response URLs fail in this wallet profile | `did:web:localhost%3A18081:…` produced `Invalid URL host`. HTTPS `localhost` reached the next check but `response_uri` was rejected. The [OpenID4VP 0.7.0 URL validator](https://github.com/inji/inji-openid4vp/blob/v0.7.0/kotlin/openID4VP/src/commonMain/kotlin/io/mosip/openID4VP/common/Utils.kt) requires HTTPS and a dotted hostname. | Use the reserved Docker-only `local.test` hostname, default HTTPS port and isolated JVM trust stores. This is a local deployment restriction, not a demonstrated security defect. |
| Request-URI-only launch is incomplete for this pinned wallet | `openid4vp://authorize?request_uri=…` was rejected for missing `client_id`. Adding unsigned parameters with DID client identification was also rejected. | Supply `client_id` plus Verify's original signed request by value. Mimoto accepts and verifies that signed envelope. |
| PE filter support is narrower than general JSON Schema | A `contains` filter was rejected for missing `filter.pattern`. | Use the supported `$.type[*]` string pattern. Do not infer general PE/DCQL conformance from this working query. |

The final [sanitized same-wallet run](../submission/evidence/2026-10-26-local-web-jsonld/README.md) checks the exact credential after reload and selects it by its private ID for presentation. Both proof checks returned true. The synthetic authorization fixture, DID adaptation and network context dependencies remain explicit.
