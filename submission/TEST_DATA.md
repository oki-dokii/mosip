# Sample test data for reviewers

Start with the [README quick start](../README.md#quick-start). The Docker mock demo creates synthetic inputs and requires no wallet account. Use the table to choose an input and compare the outcome with the [test results](TEST_EVIDENCE.md).

| Scenario | Sample input | How to use it | Expected result |
|---|---|---|---|
| Valid mock credential | Synthetic credential generated by the mock issuer | Run `pnpm demo:docker` and select the valid mock scenario in the playground | The mock verifier accepts the credential. |
| Invalid signature | Mock credential with a signature fault | Select the signature fault scenario | Verification fails. |
| Expired or wrong credential type | Mock issuer signs a deliberately expired credential or one with the wrong type | Select each signed fault scenario separately | The verifier rejects the corresponding fault. |
| Missing disclosure or nonce mismatch | Strict mock pair with a required disclosure omitted or an incorrect nonce | Select the corresponding mock scenario | The verifier rejects the presentation. |
| Local Inji Web JSON-LD journey | [Local issuer seed](../scripts/seed-local-jsonld.mjs) | Follow the local stack setup and run `pnpm demo:web-jsonld` | The wallet stores and presents the synthetic card and local Verify returns valid. |
| Browser traffic import | [Synthetic four-service HAR](../apps/bff/src/capture/fixtures/four-service.synthetic.har.json) | Use the fixture with the capture import procedure in the [API reference](API_REFERENCE.md) | Compare the sanitized exchanges with the [saved import result](../apps/bff/src/capture/fixtures/four-service.import-result.json). |
| Recorded hosted flows | [SD-JWT](../spikes/fixtures/collab-reference-wallet-sdjwt-2026-10-20.json) and [JSON-LD](../spikes/fixtures/collab-reference-wallet-jsonld-2026-10-20.json) | Open each JSON file to inspect its recorded checkpoints | Compare the dated observations with the [aggregate report](AGGREGATE_REPORT.md). |

For the full list of measured combinations and their outcomes, use the [aggregate report](AGGREGATE_REPORT.md). Live hosted flows require operator access. Public fixtures contain no reusable login credentials.
