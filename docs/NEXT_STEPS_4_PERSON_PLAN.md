# Remaining work: four-person execution plan

Updated 2026-10-22 after review of Thrissha's improvement proposal. This plan uses the stricter seven-phase checklist discussed after the original Phase 0–3 milestones. It describes work **not yet proven**, rather than renaming Reference Wallet results as all-Inji results. The proposal is a source of ideas, not evidence that those features or integrations already work here.

## Current baseline and finish line

The playground already runs Certify → Reference Wallet → Verify for SD-JWT and JSON-LD, records sanitized exchanges, replays faults, exports reports and a matrix, and runs independent mock issuer/verifier services. The X.509 mock issuer passed the public Collab Verify path. `pnpm test`, `pnpm build`, and `pnpm typecheck` passed at the Phase 3 checkpoint; see [PHASE3.md](PHASE3.md).

The remaining mandatory evidence is: an **Inji wallet** issuing, holding, and presenting JSON-LD and SD-JWT to Inji Verify (A1/A2); browser-side exchange capture without changing signed protocol values (FR-40); and a usable assisted Inji Web path for its supported format (FR-25). The one-command playground-and-mocks slice of A6 passed locally and in hosted CI; a clean-machine rehearsal and a local Inji profile remain. A dedicated persistent Collab Inji Web test account is not currently available. Current Inji Web documentation limits OpenID4VP presentation to JSON-LD, so plan SD-JWT validation with a suitable Inji mobile wallet version. A blocked external test must be reported as blocked, never marked passed. A pinned local Inji profile is the primary live-integration target after the core playground/mocks Compose path.

The four workstreams below can start in parallel. They should use separate local copies and **must not create new branches** until the user changes that rule. Person 4 already has `origin/person4/packaging-ci`; finish and review that existing branch without creating another. One integrator serializes reviewed commits and pushes to `main`; each developer pulls the latest `main` before handing over a patch or committing. No one edits another person's owned files without coordinating first. The integrator alone reconciles `README.md`, `SRS.md`, `decisions.md`, the matrix/report code, and the final acceptance report.

**Preserve contributor history without branches.** The current history has one author. Each developer should make several focused commits with their own Git name/email in their separate copy, then send `git format-patch` files. The integrator reviews and applies them in order with `git am`, which retains the original commit author. Alternatively, schedule one developer at a time to commit directly to `main` with their own identity. Do not squash, impersonate another contributor, or rewrite submitted history. Record a short handoff note with patch commit IDs and the test result. The integrator remains responsible for the final push, not for claiming sole authorship.

Suggested timebox with four developers: one day to freeze the exchange contract and start the four tracks, two to three days of parallel implementation, then one to two days for serial integration, mock smoke tests, and documentation. Based on the team's “five days remaining” estimate on 2026-10-21, the working code freeze is **2026-10-26 21:00 IST** and A1/A2 go/no-go is **2026-10-24 21:00 IST**. Adjust these if the official deadline differs. [WALLET_VALIDATION.md](WALLET_VALIDATION.md) defines the proof and blocker record; the cutoff does not declare an unavailable test passed.
